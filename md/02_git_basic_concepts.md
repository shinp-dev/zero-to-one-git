# 第2章：Gitの基本概念・コマンド・.gitignore

チーム開発の具体的な手順に入る前に、Gitの仕組み（概念）と、日常的に使用する基本的なコマンド、および不要なファイルを除外する `.gitignore` について学びましょう。

---

## 2.1 Gitの「3つのエリア」とリモートの関係

Gitでは、ファイルを書き換えてから保存・共有するまでに、以下のステージ（エリア）を経由します。

```mermaid
graph LR
    subgraph Local ["あなたのPC内 (ローカル)"]
        A["1. ワークツリー<br>(実際の作業フォルダ)"] -- "git add" --> B["2. ステージングエリア<br>(一時的なコミット待ち台車)"]
        B -- "git commit" --> C["3. ローカルリポジトリ<br>(PC内の履歴データベース)"]
    end
    C -- "git push" --> D["4. リモートリポジトリ<br>(GitHubなどの共有保管庫)"]
```

1. **ワークツリー（作業ディレクトリ）**:
   エディタ（VS Codeなど）で実際にコードを書き換えている場所です。
2. **ステージングエリア（インデックス）**:
   次のコミット（セーブポイント）に含めたいファイルを一時的に登録する場所です。
   * **なぜ直接保存せず、「ステージ」を挟むのか？**
     作業中には、一時的なメモ書きや、今回の機能追加とは関係のないファイルの編集も発生します。「今回のセーブポイントに含めるファイルだけを厳選して載せる」ために、このステージングエリアが存在します。
3. **ローカルリポジトリ**:
   あなたのPC内で、変更履歴が正式に「コミット（履歴のセーブ）」として記録される場所です。
4. **リモートリポジトリ**:
   GitHubなど、インターネット上にあるチーム共有のリポジトリです。ここに送る（プッシュする）ことで、初めて他の人に変更が共有されます。

## 2.2 まず覚えるべき基本コマンド6選（switch版）

初心者がまず迷わずに使うべき基本コマンドです。

| コマンド | 役割 | 使うタイミング |
| :--- | :--- | :--- |
| `git clone <URL>` | リモートリポジトリを自分のPCに丸ごとコピーする | 開発に参加した最初の1回だけ実行 |
| `git status` | 現在どのファイルが変更され、ステージされているかを確認する | 作業の合間に「今どうなってる？」を確認するとき |
| `git add <ファイル名>` | 変更したファイルをステージングエリア（台車）に載せる | コミットする前（※ `git add .` で全変更を一括で載せられます） |
| `git commit -m "メッセージ"` | ステージされた変更をローカルリポジトリにセーブする | 一区切りの実装が終わったとき |
| `git push origin <ブランチ名>` | ローカルのコミットをGitHub（リモート）に送信する | 自分の作業をチームに共有するとき |
| `git pull origin <ブランチ名>` | GitHubの最新の変更を自分のPCに取り込む | 朝の作業開始時など、他の人の変更を手元に反映させるとき |

> [!NOTE]
> **重要な補足：「`origin`」ってなに？**
> コマンドに出てくる `origin`（オリジン）とは、**「自分が `clone` してきた元々のGitHubリポジトリのURL」を指すニックネーム**です。
> `git pull origin main` は、「インターネット上の共有元（`origin`）の `main` ブランチから最新版を持ってきて」という意味になります。

## 2.3 不要なファイルを無視する `.gitignore`

開発を進めていると、Gitで管理（コミット）したくないファイルがどうしても出てきます。

### なぜ除外が必要なのか？
* **パスワードやアクセスキーなどの機密情報**が誤ってGitHubに公開されるのを防ぐため。
* 自動生成されるライブラリ（`node_modules` など）やビルド成果物など、容量が非常に大きく、各自のPCで自動生成できるファイルを共有しないため。
* OSが自動作成するゴミファイル（Macの `.DS_Store` やWindowsの `Thumbs.db`）で履歴を汚さないため。

### 仕組みと使い方
リポジトリのルートフォルダに `.gitignore` という名前のファイルを作成し、そこに除外したいファイル名やフォルダ名のパターンを記述します。

**`.gitignore` の記述例（Node.js / Web開発の場合）**:
```text
# パッケージフォルダ（サイズが非常に大きいため除外）
node_modules/

# 環境変数・機密情報（絶対にGitHubに上げてはいけない）
.env
*.local

# OSが自動生成する一時ファイル
.DS_Store
Thumbs.db

# ビルド成果物（実行時に自動生成されるため不要）
dist/
build/
```

`.gitignore` に書かれたファイルは、`git status` や `git add .` の対象から完全に無視されるようになり、初心者が誤って不要なファイルをアップロードしてしまうのを防ぐことができます。
