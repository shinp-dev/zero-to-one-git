チーム開発におけるGit/GitHub実践ガイド（総合目次）

本ガイドは、Git/GitHubを単なる「ツール」として使うのではなく、「なぜその操作を行うのか」「なぜチーム開発で必要なのか」という目的や背景から理解し、スムーズなチーム開発を行うための学習資料です。

全体を読みやすい長さの章に分けて解説しています。以下の目次から順番に学習を進めましょう！

📖 ガイド目次

第1章：なぜGit/GitHubが必要なのか？

  • 複数人のチーム開発で直面する課題（ファイル上書き、本番の保護など）
  • 個人開発とチーム開発の違い
  • main ブランチを直接書き換えてはいけない理由と「作業部屋（ブランチ）」の重要性

第2章：Gitの基本概念・コマンド・.gitignore

  • Gitの「3つのエリア（ワークツリー、ステージング、ローカルリポジトリ）」とリモートの関係
  • 日常的に使用する基本コマンド6選（switch版）
  • 用語解説：「origin」ってなに？
  • 不要なファイルを無視する .gitignore の役割と設定例

第3章：ブランチの命名規則

  • なぜ命名規則が必要なのか？
  • 代表的なプレフィックス（feature/, bugfix/, hotfix/, docs/, chore/）の用途
  • ブランチ作成時のルールと具体例（大文字の回避、小文字への統一など）

第4章：チーム開発のワークフロー

  • チーム開発の4大ステップ（イシュー起票、ブランチ作成、プルリク、マージ）
  • 具体的な手順とコマンド（git switch -c や git push など）
  • 重要：プルリクエストで修正依頼があった場合のスマートな再プッシュ手順
  • チーム内のレビュー時のコミュニケーション（LGTMについて）

第5章：トラブルシューティングとリカバリー方法

  • コンフリクト（衝突）が発生したときの解消ステップと競合マーカーの読み方
  • 自分の作業ブランチに最新の main の変更を取り込む方法（git pull origin main）
  • やらかしたときのレスキューコマンド集（編集の取り消し、git add のキャンセル、コミットメッセージの修正、コミットのやり直し）

第6章：手を動かして学ぶ実践ハンズオン

  • ターミナル操作の準備と設定確認（ユーザー設定、Windows改行コード設定）
  • 練習用の自己紹介テンプレート（profile_template.md）を使用した、ローカル環境での一連のワークフロー体験

💡 はじめに

まずは 第1章：なぜGit/GitHubが必要なのか？ から読み進めてみてください。 実際にコマンドを実行しながら学びたい方は、第6章：手を動かして学ぶ実践ハンズオン を開いて並行して作業することをおすすめします！
